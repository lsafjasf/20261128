# 20261128

媒体池去重候选分组与主素材替换（纯 Go，仅标准库）。

解决的问题：媒体池中存在多份同名、同长但旋转角度、帧率、编码和音频指纹不同的素材，
需要自动建立去重候选组，区分三类关系，并在用户选定主素材后只替换本组关联片段。

## 关系分类

| 关系 | 判定 |
| --- | --- |
| `identical` 完全相同 | 文件哈希一致；或视频/音频指纹距离在无损带（默认 ≤0.02）内且无容器差异（仅旋转元数据差异仍算相同） |
| `transcode` 转码副本 | 时长在容差内，视频/音频指纹在匹配带（默认 0.18 / 0.22）内，但存在旋转、帧率、编码、码率、分辨率差异或重编码噪声 |
| `different` 不同镜头 | 时长超差，或视频/音频任一指纹不匹配；永远不会进入同一组 |

安全原则：证据不足时一律判为 `different`，宁可不合并，也不误并真实不同镜头。

## 算法流水线

1. 按时长排序 + 滑动窗口，只比较时长差 ≤ `DurationTol`（默认 0.25s）的候选对。
2. 指纹在抽帧时已按显示方向（upright）计算，旋转不同的同镜头素材哈希可直接比较；
   采样数不同（帧率不同）时用最近邻重采样对齐后再算归一化汉明距离。
3. 并查集合并 `identical` / `transcode` 对，输出多成员候选组；单成员素材列为 singleton。
4. 主素材默认按直立像素量 → 帧率 → 无旋转 → 码率推荐，用户可显式指定。
5. 时间线替换只处理目标组成员引用的片段：保留 `Start/SourceIn/SourceOut`，
   记录旋转补偿角与帧率换算系数；其他组和 singleton 片段不动；重复执行幂等。

## 包结构

- `media`：素材模型、旋转归一化、视频/音频指纹距离与重采样。
- `dedup`：阈值、两两分类、并查集、候选组、主素材推荐。
- `timeline`：组作用域替换、替换报告、旋转/帧率补偿。
- `cmd/mediadedup`：CLI，内置演示与 JSON 文件模式。

## 用法

```bash
go test ./...                 # 单元 + 集成测试（含 -race）
go run ./cmd/mediadedup -demo # 内置端到端演示
go run ./cmd/mediadedup -in examples/pool.json -out result.json
```

JSON 输入包含 `assets`（指纹字段）、`clips`、`masters`。
`masters` 的键可以是组 ID（如 `G1`）或任意成员素材 ID，值为要提升为主素材的成员 ID。
输出给出每组的成员、逐对判定与理由、singleton 列表，以及替换报告和替换后的片段。

## 阈值调参

所有阈值集中在 `dedup.DefaultThresholds()`：收紧匹配带会让边界对更倾向 `different`（更安全），
放宽则提高转码召回但有误并风险；实际接入时建议用标注集校准。
